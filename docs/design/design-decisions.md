# 设计决策日志

| 决策 | 理由 | 需求引用 | 考虑的替代方案 |
|------|------|---------|--------------|
| CLI 而非 Web 界面 | 开发者工作流天然在终端；可脚本化；与 CI/CD 集成；零前端依赖 | FR-003, FR-008 | Web Dashboard（开发成本高，脱离开发者习惯）、IDE 插件（平台锁定） |
| YAML 配置文件 | 人类可读；注释支持；开发者熟悉；可版本管理 | FR-015 | JSON（无注释）、TOML（生态较小）、CLI flags only（复杂配置不可行） |
| 混合上下文策略 | 边界压缩解决阶段间上下文膨胀，子代理隔离解决任务间上下文污染；两者互补 | FR-006, FR-007 | 纯压缩（可能丢失关键信息）、纯隔离（子代理间无法共享项目上下文） |
| JSON 文件持久化 | 零外部依赖；人类可读；Git 友好；跨平台 | FR-004, NFR-006 | SQLite（需依赖）、内存映射文件（平台差异） |
| LiteLLM Proxy 而非自建适配层 | 统一 100+ 模型 API；社区维护；内置路由/回退/计费；减少自建成本 | FR-001 | 自建适配层（开发成本高、维护负担大）、OpenRouter（依赖第三方服务） |
| 阶段边界自动压缩 | 在阶段自然断点压缩，信息损失最小；上下文连贯性最好 | FR-006, NFR-001 | 滑动窗口压缩（可能切断关键上下文）、按 token 计数压缩（语义不连贯） |
| 子代理结果仅返回摘要 | 防止主控上下文膨胀；子代理内部详细交互对后续阶段通常无用 | FR-007 | 返回完整交互（上下文快速膨胀）、返回制品文件路径（需额外读取） |
| 分级权限而非沙箱 | 沙箱限制文件系统访问会阻碍代码生成和测试执行；分级权限在安全与灵活间取得平衡 | FR-010 | 完全信任（不安全）、沙箱（限制实用性） |
| 状态机驱动而非事件驱动 | 工作流阶段流转是有限的、有序的；状态机模型自然匹配 Loop Engineering 的阶段概念 | FR-003 | 事件驱动（过度工程，调试困难）、纯命令式（无法处理回退和门控） |
| 配置文件中定义权限而非硬编码 | 不同项目/团队安全要求不同；用户可按需调整；支持渐进式信任 | FR-010 | 硬编码权限（缺乏灵活性）、运行时每次询问（自主执行中断） |
| 深色主题为默认 | 开发者终端普遍使用深色主题；长时间工作减少视觉疲劳 | NFR-003 | 浅色主题为默认（与多数终端习惯不符）、仅跟随终端设置（部分终端不报告主题） |
| Nerd Font 图标 + ASCII fallback | Nerd Font 提供丰富的语义图标；ASCII fallback 确保无 Nerd Font 环境的兼容性 | NFR-006 | 仅 ASCII（视觉表现力不足）、仅 Nerd Font（部分终端不兼容） |
