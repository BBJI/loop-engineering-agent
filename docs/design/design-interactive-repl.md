## 2. 状态栏

位于终端顶部，始终显示关键信息：

```
LEA v0.1.0  │  Model: glm-4  │  Phase: design  │  $0.03/10.00
```

字段说明：
- **版本**：当前 LEA 版本
- **Model**：当前活跃模型（模型切换后实时更新）
- **Phase**：当前工作流阶段（无工作流时显示 `—`）
- **成本**：当日累计花费 / 每日预算

更新规则：
- 模型切换后立即更新 Model 字段
- 每个 LLM 调用完成后更新成本
- 阶段流转时更新 Phase

## 3. 对话区域

### 3.1 用户输入

```
❯ 帮我实现用户认证模块
```

- 提示符：`❯ ` （Nerd Font）或 `> ` （fallback）
- 输入支持多行（Shift+Enter 换行）
- 支持历史记录（上下箭头翻阅）

### 3.2 智能体响应（流式）

```
◈ 我来帮你实现用户认证模块。首先分析需求...

1. 用户注册（邮箱/密码）
2. 用户登录（JWT Token）
3. 密码重置流程

让我先检查项目结构...
◈ glm-4 | 2.1s | 1.2k tokens | $0.0012
```

- 流式输出：token 实时追加
- 模型信息行：调用完成后显示
- 区分智能体输出（◈）和用户输入（❯）

### 3.3 阶段进度

工作流执行时，实时显示阶段进度：

```
◆ 工作流启动: 实现用户认证模块
─────────────────────────────────────
◆ 阶段: req ─ 需求分析
  ○ 需求分析完成 ✓
◆ 阶段: design ─ UI/UX 设计
  ○ 设计完成 ✓
◆ 阶段: review ─ 实现评估
  ● 进行中...
  ○ 待开始: task
  ○ 待开始: dev
  ○ 待开始: test
```

- `✓` 已完成（绿色）
- `●` 进行中（青色闪烁）
- `○` 待开始（灰色）

### 3.4 检查点提示

```
△ 检查点: 需求分析阶段已完成
  制品: requirements.md, traceability-matrix.md

  ❯ 批准 / 修改 / 暂停? [批准]
```

交互方式：
- 默认选中"批准"（Enter 直接确认）
- 可输入修改意见后回车
- 输入 `pause` 暂停保存

### 3.5 权限确认

```
⚠ 权限请求: 写入文件 src/auth/login.ts
  [A] 允许  [S] 始终允许  [D] 拒绝
```

交互方式：
- `A` 或 `y` — 允许本次
- `S` — 始终允许（加入白名单）
- `D` 或 `n` — 拒绝
- Enter 默认：允许（对文件写入），拒绝（对危险命令）

## 4. 斜杠命令

### 4.1 命令列表

| 命令 | 用途 | 输出示例 |
|------|------|---------|
| `/help` | 显示帮助 | 命令列表 + 简要说明 |
| `/model` | 当前模型 | `当前: glm-4 \| 回退: deepseek-v3` |
| `/model <name>` | 切换模型 | `模型已切换: glm-4 → deepseek-v3` |
| `/model list` | 可用模型 | 模型列表 + 能力标签 |
| `/model routing` | 路由配置 | 任务类型→模型映射表 |
| `/run <desc>` | 启动工作流 | 进入工作流执行模式 |
| `/resume [id]` | 恢复工作流 | 加载并继续执行 |
| `/status` | 工作流状态 | 阶段进度面板 |
| `/config <k> <v>` | 调整配置 | `配置已更新: autonomy = full` |
| `/compact` | 压缩上下文 | `上下文已压缩: 12k → 3k tokens` |
| `/clear` | 清除历史 | `对话历史已清除` |
| `/budget` | 预算消耗 | 花费/预算 + 调用统计 |
| `/permissions` | 权限状态 | 当前权限白/黑名单 |
| `/exit` | 退出 REPL | 保存状态后退出 |

### 4.2 命令响应格式

```
❯ /model deepseek-v3
◈ 模型已切换: glm-4 → deepseek-v3
  回退模型: deepseek-v3 → glm-4
```

```
❯ /budget
◈ 预算消耗:
  今日花费: $0.03 / $10.00
  调用次数: 12
  平均耗时: 1.8s
```

## 5. 交互流程设计

### 5.1 启动流程

```
$ lea

  LEA v0.1.0 — Loop Engineering Agent
  ────────────────────────────────────
  模型: glm-4 (via LiteLLM Proxy)
  项目: /path/to/project
  工作流: 2 个未完成 (输入 /resume 恢复)

  输入需求描述开始工作流，或输入 /help 查看命令

❯ _
```

### 5.2 工作流执行中的交互

```
❯ /run 实现用户认证

◆ 工作流启动...
◆ 阶段: req ─ 需求分析
◈ 分析需求中...

[流式输出...]

◈ glm-4 | 5.2s | 3.1k tokens | $0.0031
✓ 需求分析完成

△ 检查点: 需求分析阶段已完成
  ❯ 批准 / 修改 / 暂停? [批准]

❯ 批准

◆ 进入阶段: design
◈ 设计中...

[用户可以继续输入其他指令]
❯ /model deepseek-v3
◈ 模型已切换: glm-4 → deepseek-v3
```

### 5.3 模型切换流程

```
❯ /model list
◈ 可用模型:
  glm-4          复杂任务
  deepseek-v3    代码生成
  deepseek-r1    推理
  claude-4       代码审查
  gpt-4o         通用

❯ /model deepseek-r1
◈ 模型已切换: glm-4 → deepseek-r1
  用途: 后续所有 LLM 调用使用 deepseek-r1
  提示: 路由规则仍在生效，仅覆盖默认模型
```

```

❯ /status

│  项目: my-project                    │
├──────────────────────────────────────┤

│  - task   待开始                     │
│  - dev    待开始                     │

│  模型: deepseek-r1  上下文: 45%      │

❯ /resume
◆ 恢复工作流...
◆ 继续阶段: design
```

## 6. 技术选型

### REPL 核心
- **inquirer** — 交互式提示（已在依赖中）
- **readline** — Node.js 内置行读取
- 自研轻量 REPL 循环（避免 inquirer 的重度抽象，保持对流式输出的控制）

### 状态栏
- **ansi-escapes** — 终端光标控制
- 自研状态栏渲染（用 ANSI escape codes 更新顶部行）

### 流式输出
- 复用 LLMClient 已有的 `stream: true` 支持
- 通过 `process.stdout.write()` 逐 token 输出

## 7. 配色方案

| 元素 | 颜色 | chalk 方法 |
|------|------|-----------|
| 提示符 | 白色粗体 | `chalk.bold.white` |
| 智能体输出 | 默认 | 无 |
| 模型信息 | 紫色 | `chalk.magenta` |
| 阶段名称 | 蓝色 | `chalk.blue` |
| 成功 | 绿色 | `chalk.green` |
| 错误 | 红色 | `chalk.red` |
| 警告 | 黄色 | `chalk.yellow` |
| 暗淡/辅助 | 灰色 | `chalk.dim` |
| 用户输入 | 青色 | `chalk.cyan` |
