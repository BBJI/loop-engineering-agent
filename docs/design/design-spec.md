# Loop Engineering Agent — 设计规范

## 1. 概述
- **项目**：Loop Engineering Agent (LEA)
- **版本**：1.0
- **基于**：需求文档 v1.0

本设计规范面向 CLI 工具，将传统 Web UI/UX 设计概念适配为终端界面设计。

## 2. 终端设计令牌

### 2.1 调色板（ANSI 16色 + 256色扩展）

| 令牌 | ANSI | 256色 | 用途 |
|------|------|-------|------|
| `--t-primary` | blue | #3B82F6 | 主要信息、阶段名称、激活态 |
| `--t-success` | green | #22C55E | 成功状态、完成标记、通过 |
| `--t-warning` | yellow | #EAB308 | 警告状态、待决问题 |
| `--t-error` | red | #EF4444 | 错误状态、Bug、失败 |
| `--t-info` | cyan | #06B6D4 | 提示信息、模型调用日志 |
| `--t-muted` | white(dim) | #6B7280 | 次要文本、时间戳、辅助信息 |
| `--t-accent` | magenta | #A855F7 | 子代理标记、技能名称 |
| `--t-bg` | — | #1E1E2E | 深色背景（默认深色主题） |
| `--t-text` | white | #CDD6F4 | 主要文本 |

### 2.2 图标体系（Nerd Font 兼容 + ASCII fallback）

| 令牌 | Nerd Font | ASCII Fallback | 用途 |
|------|-----------|---------------|------|
| `--icon-phase` | ◆ | [*] | 阶段标记 |
| `--icon-task` | ▶ | > | 任务 |
| `--icon-success` | ✓ | OK | 成功/完成 |
| `--icon-fail` | ✗ | FAIL | 失败 |
| `--icon-bug` | ⚑ | [BUG] | Bug 标记 |
| `--icon-model` | ◈ | [M] | 模型调用 |
| `--icon-agent` | ◎ | [A] | 子代理 |
| `--icon-skill` | ◇ | [S] | 技能 |
| `--icon-warn` | △ | [!] | 警告 |
| `--icon-progress` | ○ | - | 进行中 |

### 2.3 排版体系

| 令牌 | 样式 | 用途 |
|------|------|------|
| `--text-title` | bold + primary color | 阶段标题、命令标题 |
| `--text-subtitle` | bold | 区域标题、任务名称 |
| `--text-body` | normal | 正文、描述 |
| `--text-code` | dim + monospace | 代码片段、文件路径 |
| `--text-label` | bold + muted | 标签、键名 |
| `--text-value` | normal | 值、内容 |
| `--text-dim` | dim | 次要信息、时间戳 |

### 2.4 间距体系

| 令牌 | 值 | 用途 |
|------|-----|------|
| `--space-xs` | 1 行 | 紧凑：列表项之间 |
| `--space-sm` | 2 行 | 标准：标题与内容 |
| `--space-md` | 3 行 | 舒适：阶段之间 |
| `--space-lg` | 4 行 | 宽松：主要区域分割 |

## 3. CLI 组件规格

### 3.1 Spinner / 进度指示器

**用途**：长时间操作（模型调用、文件扫描）的等待指示
**需求追溯**：FR-008, NFR-007

**使用的令牌**：--t-primary, --text-body

**状态**：
| 状态 | 视觉变化 | 交互触发 |
|------|---------|---------|
| 运行中 | 旋转动画 `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` | — |
| 完成 | ✓ 替换 spinner，绿色 | 任务完成 |
| 失败 | ✗ 替换 spinner，红色 | 任务失败 |
| 暂停 | ⏸ 替换 spinner，黄色 | 等待用户输入 |

**实现**：使用 ora 或 clui spinner 库

### 3.2 进度条

**用途**：可量化的进度显示（迭代进度、任务完成率）
**需求追溯**：FR-011

**视觉**：
```
阶段: 需求分析 ████████████████░░░░░ 75% (3/4 任务)
迭代: 第2轮    ██████░░░░░░░░░░░░░░░ 30% (3/10 Bug修复)
```

**变体**：
- 任务进度：显示 n/m 格式
- Bug 收敛：显示趋势箭头 ↓/↑/→

### 3.3 状态面板

**用途**：工作流当前状态的全局视图
**需求追溯**：FR-011

**视觉**：
```
╭─────────────────────────────────────────────╮
│  LEA 工作流状态                              │
│  项目: my-project                            │
│  阶段: 开发实现 (5/7)  迭代: 2              │

│  ◆ 需求分析    ✓ 已完成  v1.0              │
│  ◆ UI/UX设计   ✓ 已完成  v1.0              │
│  ◆ 实现评估    ✓ 已通过  v1.0              │
│  ◆ 任务拆分    ✓ 已完成  v1.0              │
│  ▶ 开发实现    ○ 进行中  迭代 2/4          │
│  ◇ 测试验证    — 待开始                     │

│  模型: deepseek-v3  上下文: 42%            │
╰─────────────────────────────────────────────╯
```

### 3.4 交互式提示

**用途**：检查点审批、权限确认、用户选择
**需求追溯**：FR-008, FR-010

**状态**：
| 状态 | 视觉变化 | 交互触发 |
|------|---------|---------|
| 等待输入 | 黄色高亮提示文本 | 检查点到达 |
| 已批准 | 绿色 ✓ + 继续消息 | 用户输入 y/yes |
| 已拒绝 | 红色 ✗ + 原因请求 | 用户输入 n/no |
| 超时 | 黄色 ⏰ + 默认操作 | 等待超时（可配置） |

**变体**：
- 是/否确认：`继续进入设计阶段？[Y/n]`
- 多选：编号列表 + 输入序号
- 文本输入：`请输入项目名称：`

### 3.5 模型调用日志

**用途**：显示模型调用信息，便于调试和成本追踪
**需求追溯**：FR-001, NFR-005

**视觉**：
```
◈ deepseek-v3 | 1.2s | 2.1k tokens | $0.003 | chat.completion
```

**变体**：
- 紧凑模式（默认）：单行
- 详细模式（--verbose）：包含请求/响应摘要

### 3.6 子代理输出面板

**用途**：显示子代理执行结果摘要
**需求追溯**：FR-007

**视觉**：
```
╭─ 子代理: task-003 实现用户认证 ─────────────╮
│  状态: ✓ 完成                               │
│  修改文件: src/auth/login.ts, src/auth/mw.ts │
│  新增文件: tests/auth.test.ts                │

```

### 3.7 Bug 收敛图表

**用途**：可视化 Bug 修复收敛趋势
**需求追溯**：FR-009, FR-011

**视觉**：
```

轮次 3: █        1 Bug ↓
轮次 4:          0 Bug ✓ 稳定
```

## 4. CLI 界面规格

### 4.1 主交互界面

**触发**：`lea` 或 `lea run`
**需求追溯**：FR-003, FR-008, FR-011
**用户角色**：开发者

#### 布局

```
┌─────────────────────────────────────────────────┐
│  LEA v0.1.0 | 项目: my-project | 模型: glm-4   │
├─────────────────────────────────────────────────┤
│                                                  │
│  [状态面板 - 组件3.3]                            │
│                                                  │
├─────────────────────────────────────────────────┤
│                                                  │
│  [当前执行输出区]                                │
│  ▶ 执行任务: TASK-003 实现用户认证               │
│  ◎ 子代理启动...                                │
│  ◈ glm-4 | 2.3s | 1.8k tokens | chat.completion │
│  ... (模型输出流式显示)                          │
│  ✓ TASK-003 完成                                │
│                                                  │
├─────────────────────────────────────────────────┤
│  [交互区 - 仅在检查点/需要确认时显示]            │
│  △ 阶段"开发实现"已完成，是否进入测试？[Y/n]    │
│  > _                                            │
└─────────────────────────────────────────────────┘
```

#### 状态变体

| 状态 | 描述 |
|------|------|
| 正常执行 | Spinner + 流式输出 |
| 检查点暂停 | 黄色提示 + 等待输入 |
| 错误恢复 | 红色错误信息 + 重试倒计时 |
| 空闲等待 | 等待下一个任务 |
| 上下文压缩 | 黄色通知"正在压缩上下文..." |

### 4.2 命令行界面

**需求追溯**：FR-003, FR-008, FR-010, FR-015

#### 命令结构

```
lea <command> [options] [arguments]

命令:
  run [描述]           启动工作流（从需求分析开始）
  resume [id]          恢复中断的工作流
  status [id]          查看工作流状态
  list                 列出所有工作流
  skills               列出可用技能
  config               管理配置（模型、权限等）
  compact              手动触发上下文压缩
  version              显示版本信息

选项:
  --model <name>       指定使用的模型
  --auto               完全自主模式（无检查点暂停）
  --checkpoint <list>  指定检查点（逗号分隔: req,design,review,task,dev,test）
  --verbose            详细输出模式
  --dry-run            预演模式（不执行实际操作）
  --project <path>     项目目录（默认当前目录）
```

#### 关键命令流程

**`lea run`**：
```
$ lea run "开发一个用户认证系统"

  ◆ 初始化工作流...
  ◆ 加载技能: 8个技能已加载
  ◆ 连接模型: deepseek-v3 (通过 LiteLLM Proxy)
  ◆ 上下文策略: 混合（边界压缩 + 子代理隔离）

  ▶ 阶段一: 需求分析
  ────────────────────────
  [需求分析执行输出...]

  △ 检查点: 需求分析完成，是否继续？
  > y

  ▶ 阶段二: UI/UX设计
  ────────────────────────
  [设计执行输出...]
```

**`lea resume`**：
```
$ lea resume

  发现未完成的工作流:
  #1  my-project  开发实现(5/7)  迭代2  2小时前中断

  恢复哪个工作流？[1] > 1

  ◆ 从检查点恢复: 开发实现 - 迭代2 - TASK-005
  ◆ 上下文已从持久化存储恢复
  ◆ 已跳过已完成阶段: 需求分析 ✓ 设计 ✓ 评估 ✓ 任务拆分 ✓

  ▶ 继续执行: TASK-005 实现API端点
```

**`lea config`**：
```
$ lea config model

  当前模型配置:
  ┌─────────────┬────────────────┬──────────┬─────────┐
  │ 模型         │ 厂商           │ 状态      │ 默认    │
  ├─────────────┼────────────────┼──────────┼─────────┤
  │ glm-4       │ 智谱           │ ✓ 可用   │ ← 主模型 │
  │ deepseek-v3 │ DeepSeek       │ ✓ 可用   │ 回退    │
  │ claude-4    │ Anthropic      │ ✓ 可用   │ —       │
  └─────────────┴────────────────┴──────────┴─────────┘

  操作: [a]添加 [r]移除 [d]设为默认 [q]退出
```

### 4.3 配置文件界面

**需求追溯**：FR-015

**文件位置**：`~/.lea/config.yaml`

```yaml
# LEA 配置文件
version: 1

# LiteLLM Proxy 配置
litellm:
  proxy_url: http://localhost:4000
  # 或远程服务:
  # proxy_url: https://litellm.my-company.com

# 模型配置
models:
  default: glm-4
  fallback: deepseek-v3
  routing:
    simple_tasks: deepseek-v3      # 简单任务用低成本模型
    complex_tasks: glm-4           # 复杂任务用高能力模型
    code_generation: deepseek-v3   # 代码生成
    code_review: claude-4          # 代码审查
  cost_budget:
    daily_limit: 10.0              # USD
    per_task_limit: 2.0            # USD

# 工作流配置
workflow:
  autonomy: semi                   # full | semi | manual
  checkpoints:
    - req                          # 需求分析后
    - design                       # 设计后
    - review                       # 评估后
    - test                         # 测试后
  convergence:
    max_bug_rounds: 3              # 每迭代最大Bug修复轮次
    stability_rounds: 3            # 连续无Bug轮次声明稳定

# 上下文管理
context:
  strategy: hybrid                 # hybrid | compression | isolation
  compression_threshold: 0.8       # 80% 上下文使用率时压缩
  preserve_artifacts: true         # 压缩时保留制品文件

# 权限配置
permissions:
  allow_read: true                 # 读取文件自动允许
  allow_write: ask                 # 写入文件: auto | ask | deny
  allow_command: ask               # 执行命令: auto | ask | deny
  deny_commands:                   # 始终需确认的命令
    - "rm -rf"
    - "git push --force"
    - "git reset --hard"

# 技能配置
skills:
  directory: ~/.lea/skills         # 技能目录
  auto_discover: true              # 自动发现新技能

# 持久化配置
persistence:
  directory: .lea/state            # 状态存储目录（相对于项目）
  format: json                     # json | sqlite
  auto_checkpoint: true            # 阶段完成时自动保存检查点
```

## 5. 交互模式

### 5.1 检查点审批模式

```
△ ─── 检查点 ─────────────────────────────────────

  阶段"需求分析"已完成。
  制品:
    ✓ 需求文档 (15 FR + 7 NFR)
    ✓ 追溯矩阵 (22 条需求)
    ✓ 待决问题 (5 个) + 风险 (6 项)

  选项: [y]批准并继续 [n]拒绝并修改 [v]查看详情 [s]暂停

  > _
```

### 5.2 权限确认模式

```
△ 权限请求: 写入文件

  目标: src/auth/login.ts
  操作: 创建新文件 (约 120 行)

  [a]允许 [d]拒绝 [A]始终允许此类操作

  > _
```

### 5.3 错误恢复模式

```
✗ 错误: 模型调用失败

  模型: glm-4
  错误: API rate limit exceeded (429)
  已重试: 1/3

  10秒后自动重试... (按 Ctrl+C 取消)
  ═══════════════════░░░░░░░░░░░ 50%
```

### 5.4 上下文压缩通知

```
△ 上下文压缩中

  当前使用: 82% (32k/40k tokens)
  操作: 压缩"需求分析"阶段详细交互为结构化摘要
  压缩后预计: ~45%

  原始交互已保存到: .lea/state/phase-req-history.jsonl
  如需回溯: lea history req
```

## 6. 响应式行为

终端宽度自适应策略：

| 终端宽度 | 行为 |
|----------|------|
| < 60 字符 | 最简模式：仅显示阶段名 + 状态图标 |
| 60-100 字符 | 标准模式：阶段名 + 简要描述 + 进度 |
| > 100 字符 | 完整模式：阶段名 + 描述 + 进度条 + 模型信息 |

## 7. 无障碍考虑

- 所有颜色信息同时通过图标/文本传达（不依赖颜色唯一传达信息）
- Spinner 同时提供文本进度描述
- 支持不依赖 Nerd Font 的 ASCII fallback
- 交互提示支持键盘操作（y/n/数字/Enter）
- 支持 `--no-color` 选项禁用颜色
- 支持 `NO_COLOR` 环境变量（业界惯例）
